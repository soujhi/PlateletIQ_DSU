1. Architecture Decision
3-day constraint. AI agent builder. Two real data sources. Every decision below is driven by this context — not best practice in the
abstract.
LOCKED
Two-track data architecture
German LASSO model → Forecast + Actions + Overview screens (labelled DEMO MODE).
eRaktKosh scraper output → Network + Transfers screens (labelled EXTERNAL REFERENCE).
These never mix. Model does not run on scraper data. Scraper data does not feed the decision engine.
LOCKED
Backend: FastAPI on Railway
FastAPI Python 3.12. SQLite in development, PostgreSQL on Railway production. No ORM complexity beyond SQLAlchemy 2 Core
for the 3-day window. Alembic migrations from day one — not retrofitted.
LOCKED
Auth: Google OAuth, stubbed for demo
Google OAuth flow must be implemented. For hackathon demo, a single demo user is pre-seeded so judges do not have to create
accounts. All API endpoints require auth header — no open endpoints except /health.
LOCKED
Frontend: existing UI, API-connected
Do NOT redesign. Do NOT rewrite screens from scratch. Install TanStack Query, replace hardcoded arrays with useQuery hooks, add
loading/error states. Every screen keeps its visual identity exactly.
LOCKED
Inventory: seeded demo data
PlateletIQ does not have a live inventory feed from any Indian hospital. Seed one demo bank (Govt. General Hospital Chennai) with
realistic platelet units. All seeded records carry demo_mode=true. UI shows DEMO DATA badge on inventory.
LOCKED
eRaktKosh: load from scraper CSV
The student's scraper has produced eraktkosh.db with 6,183+ rows across 32 districts. On startup, the backend loads this as the
external inventory snapshot. No live scraping in production — scraper runs separately and exports JSON for import.
LOCKED
Model: joblib file, adapter class
plateletiq_model.joblib + model_adapter.py are the source of truth. Antigravity calls PlateletDemandModel.predict(history, dates). Do
not recreate the feature pipeline. Do not retrain. Do not modify coefficients.
LOCKED
No Docker, no Kubernetes
Vercel for frontend (automatic from git). Railway for backend (Procfile or railway.toml). Both deploy from the same monorepo. 3 days
is not enough time to debug container builds.

2.2 Domain Models
CORE ENTITIES — EVERY FIELD IS REQUIRED UNLESS MARKED OPTIONAL
Bank
id, name, code, city, state, district, timezone, latitude, longitude, active, created_at
One row per blood bank. Demo bank: code=TN-GGH-001, name=Govt. General Hospital Chennai.
BankMembership
id, user_id, bank_id, role [TECHNICIAN|OFFICER|COMMITTEE|ADMIN], active
A user may belong to multiple banks. Role is per-bank. Admin assigns roles.
InventoryUnit
id, bank_id, bag_id UNIQUE, component_type [RDP|SDP|UNKNOWN], blood_group, collection_at, 
expiry_at, status [AVAILABLE|RESERVED|ISSUED|EXPIRED|DISCARDED|TRANSFER_PENDING|TRANSFERRED_OUT|NON_CLINICAL], source_type [OPERATIONAL|SEEDED], version
Source of truth for PlateletIQ-owned units. version is an integer for optimistic locking.
InventoryEvent
id, unit_id, bank_id, event_type, actor_user_id, occurred_at, reason, metadata_json
Immutable. Every status change produces an event. Never update or delete rows.
ForecastRun
id, bank_id, model_version, status [RUNNING|SUCCEEDED|FAILED], started_at, completed_at, h
istory_end, history_days, error_message
One row per model execution. Scheduled nightly. Failed runs do not overwrite last success.
Forecast
id, bank_id, forecast_run_id, forecast_date DATE, horizon_day INT, q50 FLOAT, q67 FLOAT, q
90 FLOAT, model_version, generated_at
One row per (forecast_run_id, forecast_date). 7 rows per run for 7-day horizon.
Recommendation
id, bank_id, forecast_run_id, action [HOLD|PROCURE|COLLECT], quantity INT, reason_summary,
 drivers_json, created_at, expires_at, status [ACTIVE|CONFIRMED|ADJUSTED|EXPIRED|SUPERSEDED]
One active recommendation per bank at any time. Confirmation creates RecommendationAction.
Requisition
id, bank_id, request_ref, ward, priority [ROUTINE|URGENT|EMERGENCY], clinical_indication, 
platelet_count FLOAT, bleeding_status BOOL, units_requested INT, component_requested, status, concordance_flag BOOL, guideline_note, submitted_at
No patient name, MRN, phone or address. Concordance flag set by decision engine on submit.
TransferOpportunity
id, source_bank_id, destination_bank_id, component_type, potential_quantity, source_freshn
ess_hours FLOAT, destination_risk_score FLOAT, expiry_window_hours FLOAT, status [OPEN|REVIEWED|OFFERED|EXPIRED|CLOSED], created_at
Derived from eRaktKosh snapshot + destination forecast. Recalculated on each snapshot import.
ExternalSnapshot
id, source TEXT, retrieved_at, parser_version, status, record_count
One row per eRaktKosh import. Never mutated after creation.
ExternalInventoryRecord
id, snapshot_id, hospital_name, state, district, component_type, reported_quantity INT, so
urce_entry_date, retrieved_at
One row per hospital-component in the snapshot. source_entry_date from eRaktKosh entrydate field.
AuditLog
id, actor_user_id, bank_id, action, entity_type, entity_id, before_json, after_json, creat

Immutable. Never allow UPDATE or DELETE on this table. All sensitive mutations log here.

5. Model Integration
The model is trained. The adapter is written. Antigravity connects it to the FastAPI forecast router. Nothing else.
5.1 What the model was trained on
Dataset: RWTH Aachen University Hospital, Germany. 4,018 daily observations, 2008-01-01 to 2018-12-31.
Source: Schilling et al., JMIR Med Inform 2022;10(2):e29978. Appendix 1 (medinform_v10i2e29978_app1.xlsx).
Target variable: Transfused (daily platelet units issued). Target transform: sqrt(units). Inverse at inference.
Split: 80% train (3,214 days, 2008-2014), 20% test (804 days, 2015-2018). Strictly temporal — no shuffling.
Validation: Walk-forward (rolling-origin) cross-validation. 12 folds. No future data leaks into any fold.
Algorithm: LASSO (L1 penalised linear regression). Alpha=0.01. 37 features, 20-21 active after regularisation.
Active feature groups: day-of-week (weekend biggest negative), rolling averages, lag-2 and lag-21, trend, holiday.
Leakage test: labels shuffled -> MASE degrades to 1.127. Confirms model learns real signal, not data artifacts.
5.2 What the model does NOT do
Does not predict demand for Indian hospitals. German-trained pattern is the proxy.
Does not output blood-group-level forecasts. Demand is total units per day.
Does not incorporate dengue signal in its features. Dengue drives the Camp Planning screen separately.
Does not output a confidence score. The 'Confidence: High' in ActionsScreen is wrong — remove it.
Does not adapt to drift automatically. Retraining requires a new CSV and a new run.
5.3 Adapter interface — exact calling convention
Backend calls the adapter exactly as follows. Antigravity must not alter this interface.
from ml.model_adapter import PlateletDemandModel
import pandas as pd
# On startup — load once, keep in memory
model = PlateletDemandModel(path='ml/plateletiq_model.joblib')
# In forecast router — called by scheduled job
async def run_forecast(bank_id: str, demand_history: list[dict]):
    # demand_history: [{date: '2024-01-01', units_issued: 14}, ...]
    series = pd.Series(
        {pd.Timestamp(r['date']): float(r['units_issued']) for r in demand_history}
    ).sort_index()
    forecast_dates = [today + timedelta(days=i) for i in range(1, 8)]
    result = model.predict(series, forecast_dates)
    # result.forecast: [{date, q50, q67, q90}, ...]
    # result.model_version, result.metadata, result.limitations
    return result
# Minimum history: 30 days. Recommended: 90+ days.
# For demo: use the last 90 days of the German test set as seed history.
5.4 Scheduled forecast job (ARQ)
1. Load latest demand history for the bank (all InventoryEvent type=ISSUED, last 365 days).
2. Validate: minimum 30 rows, no negatives, gaps < 14 days.
3. Call model.predict(series, next_7_dates). Catch exceptions.
4. Validate output: 7 rows, q50 values between 0 and 200.
5. Persist ForecastRun (SUCCEEDED) + 7 Forecast rows in one transaction.
6. Call decision_engine.generate_recommendation(bank_id, forecast_run_id).
7. Supersede any previous ACTIVE recommendation for this bank.
8. On failure: persist ForecastRun(FAILED, error_message). Do not touch last succeeded run.
Default schedule: 05:00 local time daily. Officer can trigger manually via POST /forecast/runs.

6. Decision Engine — HOLD / PROCURE / COLLECT
This is the product differentiator. The model predicts demand. The decision engine turns demand + inventory into an action. Pure
Python, deterministic, fully unit-testable.
6.1 Inputs
q50_7d
Sum of q50 over 7 forecast days — the expected demand
 q67_7d
Sum of q67 over 7 days — the order-point (67th percentile)
 usable_now
Units with status=AVAILABLE and expiry_at > now
 usable_by_day
Units usable on each of the next 7 days (respects expiry — a unit expiring tonight is NOT usable on
Tuesday)
 pending_requisitions
Units reserved for unfulfilled requests
 safety_stock_alpha
Configurable multiplier, default=13. Bank-specific.
 lead_time_days
Days until a procurement/collection arrives, default=2
 no_delivery_days
Set of weekdays with no delivery (e.g. Sat, Sun)
6.2 Decision algorithm
# Step 1 — Compute usable coverage per day
for each day d in [today+1 .. today+7]:
    usable_on_d = units where expiry_at > d AND status = AVAILABLE
    demand_on_d = q50[d]
    coverage_gap[d] = usable_on_d - demand_on_d
# Step 2 — Find the first day coverage goes negative
first_gap_day = min(d for d in days if coverage_gap[d] < safety_stock_floor)
# safety_stock_floor = q67_7d * alpha / 7  (daily safety minimum)
# Step 3 — Decision
if all(coverage_gap[d] >= 0 for d in days):
    action = HOLD
    quantity = 0
elif first_gap_day > today + lead_time_days:
    # Gap exists but not urgent — standard procurement
    action = PROCURE
    quantity = ceil(q67_next_horizon - usable_net_of_expiry)
else:
    # Urgent — active collection (e.g. apheresis donors today)
    action = COLLECT
    quantity = ceil(immediate_deficit)
# Step 4 — Check for transfer opportunity BEFORE returning PROCURE
if action == PROCURE:
    opportunities = get_open_transfer_opportunities(bank_id)
    if opportunities and opportunities[0].potential_quantity >= quantity * 0.5:
        # Surface transfer first — cheaper than fresh procurement
        recommendation.transfer_opportunity = opportunities[0]
# Step 5 — Build drivers (max 4, human-readable)
drivers = compute_top_drivers(coverage_gap, expiry_risk, pending_reqs, seasonal_index)
6.3 FIFO enforcement
When issuing, always select the unit with the earliest expiry_at first.
If a technician manually selects a unit and an older eligible unit exists: return 200 with a warning (do not block), require
override_reason in the request.
If override_reason is empty: return 422 FIFO_OVERRIDE_REQUIRED.
Log fifo_override=true + reason in IssueEvent and AuditLog.
Never allow two concurrent transactions to issue the same bag_id. Use SELECT FOR UPDATE on the unit row.
6.4 Concordance check (requisitions)
platelet_count < 20 x10^9/L, no active bleeding → CONCORDANT (prophylactic threshold, WHO Dengue §3.4)
platelet_count < 50 x10^9/L, active_bleeding = true → CONCORDANT (therapeutic threshold)
platelet_count < 50 x10^9/L, DIC_confirmed = true → CONCORDANT
Anything outside the above → concordance_flag = false, guideline_note = 'Request falls outside WHO prophylactic (<20) and
therapeutic (<50 with bleeding) thresholds. Review recommended.'
The word 'inappropriate' must never appear in the UI or API response.
Issue anyway is always available. The system never blocks a transfusion.

Scraper is a separate process. Backend only imports its output JSON. Do not wire the scraper into the FastAPI server.

The model does not support it. Do not add it.

Vercel + Railway natively. No containers needed.
✕  Websockets / real-time push
TanStack Query polling is sufficient for a demo.

PlateletIQ is a blood bank operations tool. No donor registration, no donor portal, no donor SMS.

Never. Not now, not post-hackathon. The product is decision support for blood bank technicians. Requisition concordance flags are
